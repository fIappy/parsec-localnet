# Protocol reference (observed on 150-105c)

All facts below were captured from the live client/host and validated by a
working relay. Fields marked *inferred* are not directly observed but required
by the parsers.

## HTTP

Host: `kessel-api.<env>` (`kessel-api.parsec.app` by default; the env comes from
the `app_environment` config key). TLS 1.2 minimum, no ALPN.

Common headers on every request:

```
Authorization: Bearer <session_id>
User-Agent: parsec/<build> (loader: <n>) <os> libmatoya/5.0
X-Parsec-OS: Windows 11
X-Parsec-OS-Version: 10.0
X-Parsec-Platform: windows
X-Parsec-App-Version: <build>
X-Parsec-Device-ID: <32 hex>
```

Routes the client needs:

| route | response |
|---|---|
| `GET /me` | user object (below) |
| `GET /v2/hosts?mode=desktop` | host list |
| `POST /events` | `204 No Content` (telemetry; can be ignored) |
| `GET /friend-requests?direction=incoming` | `{"data":[]}` |
| `GET /data/errors/codes.json` | must return 200 with the real catalog (`codes.json`); a 404 raises the UI banner `Error [404] Failed request to /data/errors/codes.json` |
| `GET /data/notifications/*.json` | `{"display": false}` |
| `GET /data/changelog/content.json` | 404 is tolerated |
| `POST /v2/auth` | `{"email","password","tfa"}` → `{"session_id": "<64 hex>"}`; any credentials accepted. Needed for the unpatched macOS UI (it shows the login screen instead of Computers) |
| `PATCH /auth/sessions/elevate` | same `{"session_id"}` shape (re-auth prompt) |

### /me

```json
{"data":{
  "id":1,"name":"lan","email":"","warp":false,"staff":false,"team_id":"",
  "is_confirmed":true,"team_is_active":false,"is_saml":false,
  "is_gateway_enabled":false,"is_relay_enabled":false,"has_tfa":false,
  "team_enforce_tfa":false,"can_upgrade_session":false,"can_downgrade_session":false,
  "is_client_mode_disabled":false,
  "app_config":{"ws_host":{"value":"kessel-ws-v2.parsec.app"}},
  "app_config_v2":{"ws_host":{"value":"kessel-ws-v2.parsec.app"}},
  "cohort_channel":"release-alpha","app_ui_channel":"release-ui",
  "session_scopes":["api.writer"],"marketing_opt_in":null,
  "is_out_of_compliance":false,"is_managed_team_machine":false}}
```

The real server also returns `host_peer_id` and `client_peer_id` (stable per
device, 27-char base62). They are not required for the relay; add them if a
future build starts using them.

`app_config.ws_host` is the only config value that matters: it is where the
client opens the WebSocket.

### /v2/hosts

```json
{"data":[{
  "user":{"id":1,"name":"lan","warp":false,"team_id":"","has_avatar":false},
  "peer_id":"3M3M7QWWebETkcyDyR5uXiggoQn",
  "Connections":null,"game_id":"","description":"","max_players":20,
  "mode":"desktop","name":"HOSTNAME","event_name":"","players":0,
  "public":false,"guest_access":false,"online":true,"self":false,
  "build":"150-105c","OS":"Windows 11","activity":0}],
 "has_more":false}
```

`peer_id` is what the client puts in `offer.payload.to`.

Two rules learned from the 150-105c UI:

- Exclude the requesting device (match `X-Parsec-Device-ID`) or the local
  "This Computer" card is duplicated.
- List **online hosts only**. This build renders an `online:false` record as a
  normal, connectable card and gives no offline state, so a dead entry looks
  live and every Connect hangs.

## WebSocket

```
GET /?session_id=<session>&role=host|client&version=1&build=<build>&sdk_version=<uint>
Upgrade: websocket
Authorization: Bearer <session>
```

`sdk_version` was `393216` (0x60000). After the 101, every message is a JSON
text frame:

```json
{"version":1,"action":"<name>","payload":{...}}
```

### host -> server: conn_update

```json
{"action":"conn_update","version":1,"payload":{
  "device_id":"8b5a0cc724857e840ae7902d357c7f92","desc":"","players":0,
  "name":"EATER-PC","os":"Windows 11","platform":"windows","mode":"desktop",
  "service_v":-1,"game_id":"","app_v":"150-105c","sdk_v":393216,"guests":[],
  "public":false,"max_players":20,"secret":"","loader_v":18,"os_v":"10.0"}}
```

The server keys host identity by `name` and answers nothing. A host reconnects
freely; `guests` is a live list of connected guest ids.

### client -> server: offer

```json
{"action":"offer","version":1,"payload":{
  "attempt_id":"f7c8640b-3b19ff91-59efb819-278ef784-98665c04-0a83aca8",
  "access_link_id":"",
  "data":{"mode":1,"ver_data":1,
    "versions":{"bud":1,"control":1,"p2p":1,"audio":1,"init":1,"video":1},
    "creds":{"fingerprint":"<sha256 hex>","ice_pwd":"<base64>","ice_ufrag":"<base64>",
             "aes256":"<64 bytes hex>"}},
  "to":"<host peer_id>","secret":""}}
```

`attempt_id` is generated by the client (6 hex groups). `data` is opaque to the
server; the host parses it. `secret` is the host secret for share links, empty
for account connections.

### server -> host: offer_relay

```json
{"action":"offer_relay","version":1,"payload":{
  "from":"<server-assigned client id>",
  "attempt_id":"<echo>",
  "data":{ ...offer.data... },
  "is_owner":true,
  "skip_approval":true,
  "permissions":{"gamepad":true,"keyboard":true,"mouse":true},
  "user":{"name":"lan","id":1,"has_avatar":false}}}
```

All of `is_owner`, `skip_approval`, `permissions`, `user` are required by the
host-side parser. `data.mode` (1 = desktop) is also read there.

### host -> server: answer

```json
{"action":"answer","version":1,"payload":{
  "attempt_id":"<echo>","approved":true,"data":{ ...answer ICE/AES... }}}
```

### server -> client: answer_relay

```json
{"action":"answer_relay","version":1,"payload":{
  "from":"<host peer id>","attempt_id":"<echo>","data":{...},"approved":true}}
```

### candex (both directions)

Client/host send `candex` with the attempt id and one candidate:

```json
{"action":"candex","payload":{"attempt_id":"<echo>",
  "data":{"ip":"192.168.1.2","port":22187,"lan":true,"from_stun":false,"sync":false}}}
```

The server forwards it as:

```json
{"action":"candex_relay","payload":{
  "from":"<sender id>","attempt_id":"<echo>",
  "data":{"ip":"...","port":0,"lan":false,"from_stun":false,"sync":false}}}
```

`lan` selects the log label (LAN/WAN) on the receiver; the candidate list order
is what ICE uses.

### close

```json
{"action":"close","payload":{"reason":"HOST_NOT_FOUND"}}
```

Reason -> SDK error mapping: `HOST_NOT_FOUND` 99, `USER_UNCONFIRMED` 100,
`TFA_REQUIRED` 101, `NO_PERMISSION` 112, `INVALID_MSG` -6106,
`ACCESSLINK_*` 200..204, `TEAM_DEACTIVATED` -3010, `OUT_OF_COMPLIANCE` 102,
`INVALID_SESSION` -3008, anything else -6105.

### sdk

`{"action":"sdk","payload":{...}}` is handed to the SDK callback verbatim.
Ignoring it is safe for a LAN relay.

## Relay contract implemented by privsvr.py

- Key clients by a unique id per connection; the host learns it as `from`.
- Route `answer`/`candex`/`close` by `attempt_id` to the peer of that attempt
  (client sender -> host connection, host sender -> client connection).
- A host that disconnects stays listed for 2 s (bridges immediate reconnects);
  a host silent for 45 s (no WS frame at all; hosts ping every 30 s) is treated
  as gone and dropped, so sleep/Wi-Fi drops do not leave a phantom card.
- Queue `offer`s for an offline peer for a short grace (3 s) and flush them on
  the next `conn_update`; when the grace expires, answer the client with
  `close {reason:"HOST_NOT_FOUND"}` instead of leaving the attempt pending.
- Cancel queued offers when the client's WebSocket goes away.
- Strip whitespace/`\r` from every string field before routing.

## Media

After the final candidate exchange the peers agree on an ICE pair and switch to
BUD over UDP (AES-GCM-256, keys from `creds.aes256`). The server is not in the
media path; latency is the host pipeline plus the chosen pair.
